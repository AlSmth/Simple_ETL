# Handyman Data Platform

Сервис мастеров на час в Ереване: от заявки в Telegram-боте до дашборда и AI-агента.

```
Заказчик ──► Telegram-бот ──► PostgreSQL (handyman) ──► Airflow ETL ──► MRR ─► STG ─► DWH ──► Power BI
   ▲             ▲  ▲                    │                                              │
   │             │  └── Мастер берёт и закрывает заявки                                 │
   │             │                       ▼                                              ▼
   └── рассылка ─┴──── AI-агент (Claude) ◄── менеджер пишет запрос текстом ── читает обе базы
```

- **Бот** (`app/bot`) — заявки от заказчиков на трёх языках (RU / EN / HY), мастера берут и
  закрывают их, менеджеры видят всё и одобряют мастеров.
- **ETL** (`dags/handyman_etl.py`) — Airflow раз в сутки инкрементально переносит данные бота в
  MRR, затем в STG и DWH.
- **DWH** — факты и измерения для Power BI (`Отчет.pbix`) и агента.
- **Агент** (`app/agent`) — менеджер пишет боту обычным текстом, агент отвечает по данным и
  готовит рассылки заказчикам. Отправляются они только после кнопки «Отправить».

## Запуск

Нужен Docker Desktop.

1. Создайте бота у [@BotFather](https://t.me/BotFather) и скопируйте токен. Возьмите **новый** токен:
   если этим ботом уже кто-то опрашивает Telegram, обновления будут теряться.
2. Скопируйте `.env.example` в `.env`, впишите `BOT_TOKEN` и `ANTHROPIC_API_KEY` (без ключа бот
   работает, но агент выключен).
3. Поднимите всё:

   ```bash
   docker compose up -d --build
   ```

   Поднимутся PostgreSQL с базами `handyman`, `mrr`, `stg`, `dwh` (схемы создаются из
   `sql/init` при первом старте), Airflow и бот.
4. Напишите боту `/myid`, впишите id в `MANAGER_CHAT_IDS` в `.env` и перезапустите бота:
   `docker compose up -d bot`.

| Что | Где |
|---|---|
| Airflow | http://localhost:8080 (admin / admin), DAG `handyman_etl` |
| PostgreSQL с данными | `localhost:5436`, пользователь `app` / `app` |
| Power BI | подключение к `localhost:5436`, база `dwh` |

Подключения Airflow (`postgres_operational`, `postgres_mrr`, `postgres_stg`, `postgres_dwh`)
задаются переменными окружения в `docker-compose.yaml`, руками создавать их не нужно.

## Роли в боте

**Заказчик** — `/start`: язык → категория → описание (+фото) → район → адрес → способ связи →
телефон → проверка → «Отправить». `/orders` — свои заявки и отмена, пока мастер не взял.
Бот сам пишет заказчику, когда мастер взял заявку и когда закрыл.

**Мастер** — `/master` отправляет заявку в команду, менеджер одобряет кнопкой. Новые заявки
приходят мастерам без телефона и адреса, с кнопкой «Взять». Кто первым нажал, тот и взял: второму
бот ответит, что заявка занята. Взявший видит контакты, может «Отказаться» (заявка снова
уходит всем) или «Выполнено»: выбрать работу из каталога, указать сумму, подтвердить.
`/new` — свободные заявки, `/my` — свои в работе.

**Менеджер** (`MANAGER_CHAT_IDS`) получает все заявки с контактами, события по ним и заявки в
мастера. Любой текст, который не команда, уходит агенту. `/reset` — новый диалог с агентом.

## AI-агент

Агент работает на Claude API (`AGENT_MODEL`, по умолчанию `claude-opus-5-5`) и умеет две вещи:

| Инструмент | Что делает |
|---|---|
| `run_sql` | Один `SELECT` в базе бота (живые данные) или в DWH (история). Роль `agent_ro` с правами только на чтение, транзакция `READ ONLY`, таймаут 10 с, до 200 строк. |
| `prepare_broadcast` | Готовит рассылку: получатели и текст сохраняются в `broadcasts` со статусом `pending`. Сам агент ничего не отправляет. |

Примеры запросов:

- «Сколько заявок пришло на этой неделе и сколько ещё без мастера?»
- «Выручка по категориям за октябрь»
- «Напиши заказчикам с открытыми заявками по сантехнике, что мастер приедет завтра до 12»

На рассылку бот показывает превью: текст, число получателей и их язык. Сообщения уходят только
после кнопки «✅ Отправить». Каждое сообщение пишется в `message_log`, а заблокировавшие бота
заказчики помечаются и в следующие рассылки не попадают. Итог отправки агент видит в начале
следующей реплики. Агент пишет каждому заказчику на его языке; если языки разные, он готовит
несколько рассылок.

Для запросов используется серверный fallback (`fallbacks: "default"`): если классификаторы
безопасности отклонят запрос, Claude API сам повторит его на рекомендованной модели.

Агента можно запустить и в терминале (рассылку подтверждаете `y`):

```bash
pip install -r requirements.txt
python -m app.agent
```

## Данные

| База бота (`handyman`) | Слои (`mrr_` / `stg_` / `dwh_`) |
|---|---|
| `orders` — заявки: статус, район, мастер, даты | `fact_orders` (+ `order_day`, `hours_to_assign`, `hours_to_complete` в DWH) |
| `order_details` — выполненная работа и сумма | `fact_order_details` (+ `revenue` в DWH) |
| `customers` — заказчики (id = Telegram id) | `dim_customers` |
| `masters` — мастера | `dim_masters` |
| `products`, `categories` — каталог услуг | `dim_products`, `dim_categories` |
| `message_log` — все сообщения заказчикам | `fact_messages` |
| `broadcasts` — рассылки агента | — |

Телефоны, адреса, описания и фото в аналитику не попадают: они нужны только боту.

### ETL

1. Для каждой таблицы берётся High Water Mark — время последней загрузки (`dwh_high_water_mark`).
2. Читаются строки с `updated_at` новее HWM минус 10 минут. Перекрытие нужно, чтобы не потерять
   строку, которая закоммитилась позже, чем проставлен её `updated_at`. Повторы безопасны.
3. Upsert в MRR пачками (`INSERT … ON CONFLICT DO UPDATE`).
4. HWM сдвигается на максимальный `updated_at` из загруженного.
5. MRR → STG → DWH: `TRUNCATE` и вставка в одной транзакции, поэтому дашборд никогда не видит
   пустую таблицу.
6. Каждая задача пишет строку в `etl_logs` (статус, время, длительность, ошибка).

`updated_at` в базе бота обновляют триггеры, приложению об этом думать не нужно.

## Структура

```
app/
  config.py, db.py, texts.py, notify.py   настройки, запросы к базе, тексты RU/EN/HY, отправка заказчикам
  bot/      customer.py, master.py, manager.py — сценарии ролей; main.py — запуск
  agent/    agent.py — цикл tool use, tools.py — инструменты, prompt.py — системный промпт
dags/handyman_etl.py   DAG Airflow (список таблиц — TABLES)
sql/init/              схемы всех баз, применяются при первом старте PostgreSQL
Отчет.pbix             дашборд Power BI
```

Добавить таблицу в ETL: создать её в `sql/init/20_layers.sql` во всех трёх слоях и дописать
строку в `TABLES`.

## Возможные улучшения

- Дашборд: обновить `Отчет.pbix` под новую схему DWH (районы, скорость назначения мастера,
  рассылки).
- Хранить состояние диалогов бота в Redis: сейчас незаконченное заполнение заявки сбрасывается
  при перезапуске.
- Проверки качества данных и SCD Type 2 для справочников.
- Мониторинг ETL и бота в Grafana, CI/CD.
